# titan2-boot

[English version](README.md)

Минимальный загрузчик второй ступени для Unihertz Titan 2 (MT6878): aarch64, без ОС. Стоковый LK
не заменяется и не перепрошивается: он загружает этот образ из `boot_a` так же, как ядро
(распаковывает по адресу 0x40000000 и передаёт управление на EL1, в x0 — FDT, который уже собрал
стоковый LK). Как стоковый LK загружает образ, описано в titan2-docs:
`docs/lk-boot-requirements.md`.

**В образы alpha1 не входит.** На телефон ещё не прошивался и не проверялся.

## Состояние

Заготовка «признаки жизни»:
- правильный заголовок arm64 Image, поэтому LK (и любой загрузчик arm64) его принимает;
- читает FDT из x0, пишет `bootargs` и другие сведения в UART (`0x11001000`, 921600);
- рисует меню во фреймбуфере LK (`0xfe04f000`, ARGB8888, 1440x1440);
- читает громкость вверх/вниз из матрицы клавиш;
- в простое сбрасывает сторожевой таймер;
- пункты Fastboot / Recovery / Reboot работают через `syscon-reboot-mode` и PSCI.

Ядро он намеренно **ещё не загружает**. Включить это — отдельный шаг, для которого нужно железо;
ничто в этом репозитории не прошивает устройство.

Что нужно подтвердить на железе (отмечено в коде):
- точный бит громкости вверх в матрице (`io.c:key_vol_up`);
- панель работает в командном режиме DSI, поэтому запись во фреймбуфер видна только после запуска
  кадра DSI (см. titan2-docs: `docs/hardware/display.md`). Это ещё не сделано; пока надёжный
  вывод — UART.

## Сборка

```
make TOOLCHAIN=/путь/к/clang-r574158
```

Компилятор — AOSP clang r574158 (clang 21). Результат: `out/titan2-boot.bin` (сырой Image) и
`out/titan2-boot.bin.gz`. Makefile запускает `tools/check-image.py`, который офлайн проверяет
заголовок и размер.

## Дальше

1. Встроенная libfdt и копирование узлов для DT mainline.
2. Запуск кадра DSI в командном режиме, чтобы меню было видно.
3. Загрузка ядра (за явным флагом сборки); проверяется, только когда пользователь решит прошить
   `boot_a`.
4. Потом: чтение UFS, чтобы ядра лежали в настоящих разделах, а не внутри `boot_a`.

## Источники

Сведения о железе (адреса, значения регистров, состояние, в котором стоковый
загрузчик оставляет железо) получены с самого телефона: чтение регистров на
устройстве, заводское дерево устройств и журналы загрузки, собственные модули
ядра телефона, объявленные под GPL, и анализ поведения стокового загрузчика
(его код не воспроизводится); для сравнения — публичные исходники MediaTek под
GPL и upstream Linux. Проприетарного кода, прошивок и бинарных файлов здесь нет.
